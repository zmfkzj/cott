# portfolio-cost

## 예제 목적
구조체 목록을 순서대로 평가하고 처음 실패한 보유 항목을 오류 enum으로 보고하는 예제입니다.

## 핵심 포인트
- `Holding`은 `I64` 주식 수와 `F64` 가격을 가집니다. `calculate_portfolio_cost`는 성공한 총액이 유한하고 음수가 아님(`0.0 <= total <= MAX_F64`)을 형식 절로 선언합니다.
- `doc`은 총액을 `0.0`에서 시작해 목록 순서대로 누적한 주식 수 곱하기 가격으로 정의하고 오류 순서를 정합니다. 보유 항목은 목록 순서로, 한 항목 안에서는 `NegativeShares`, `NonFinitePrice`, `NegativePrice` 순으로 검사하며, 곱이나 누적 합계가 유한하지 않은 항목에서 `TotalOverflow`를 보고합니다. 이 조건들은 목록 원소에 걸쳐 있고 절은 원소 전체를 한정할 수 없으므로 네 오류 모두 무조건 오류로 남습니다.
- 시나리오는 정확한 총액, 뒤쪽 `NegativeShares`보다 앞쪽 `NegativePrice`가 우선하는 경우, 가격보다 주식 수를 먼저 검사하는 경우, 곱의 오버플로, 뒤쪽 잘못된 항목보다 먼저 일어나는 누적 합계 오버플로를 관찰합니다. 연결된 두 requirement는 `observed`이며, 이는 이 입력들에 대한 제한된 증거일 뿐 다른 포트폴리오에 대한 증명이 아닙니다.
- 검증되지 않은 것: 시나리오는 NaN이나 무한대 가격을 만들 수 없고 자동 후보에도 없으므로 `NonFinitePrice`는 semantic coverage에서 `unobserved`로 남습니다. 그 밖의 총액은 유한하고 음수가 아니라는 경계로만 검사합니다.
